# Конфигурационное управление — вариант 21

Ассемблер и интерпретатор учебной виртуальной машины из `абоба.pdf`,
страницы 88–91. Ветка `stage-3` содержит **этапы 1–3**: CSV, машинный код
и интерпретатор памяти. `main` и `stage-2` сохраняют предыдущие этапы.

## Запуск

Нужен Python 3.9 или новее. Само приложение использует только стандартную
библиотеку; отдельная сборка не требуется. Команды выполняются из корня:

```bash
python3 -m src.assembler examples/spec.csv build/spec.bin --test
make run
```

Ассемблер принимает два позиционных аргумента: исходный CSV и путь
результата, затем необязательный `--test`. Создаётся двоичный файл,
недостающие родительские каталоги создаются автоматически. `--test`
печатает команды по шесть байт:

```text
Assembled instructions: 4
0x8F, 0x62, 0x00, 0x00, 0x60, 0x00
0x57, 0x03, 0x00, 0x00, 0x26, 0x00
0x77, 0x78, 0x03, 0x00, 0x00, 0x00
0xF5, 0x98, 0x12, 0x00, 0x80, 0x00
```

## Язык CSV

Заголовка нет. Одна строка — одна команда. Порядок операндов соответствует
полям B, C, D из PDF. Поддерживаются десятичные числа, `0x` для hex,
кавычки CSV, пробелы по краям, UTF-8 с BOM, пустые строки и строки
комментариев, первое поле которых начинается с `#`. Имена команд
регистрозависимы. Меток, переходов и inline-комментариев нет.

| Команда | Поля | Действие УВМ |
| --- | --- | --- |
| `LOAD_CONST,B,C` | A=15; B:29 бит; C:6 бит | R[C] = B |
| `READ_MEM,B,C` | A=23; B:26 бит; C:6 бит | R[C] = M[B] |
| `WRITE_MEM,B,C` | A=55; B:6 бит; C:6 бит | M[R[C]] = R[B] |
| `MUL,B,C,D` | A=53; B:6 бит; C:26 бит; D:6 бит | M[R[D]] = M[C] * R[B] |

Все поля беззнаковые. Допустимые значения: `0..2**width-1`.
УВМ имеет 64 регистра; адресные поля памяти содержат 26 бит.
На этапе 3 исполняются LOAD_CONST, READ_MEM и WRITE_MEM. MUL уже
ассемблируется, но его исполнение добавляется только на этапе 4.
Ошибочные числа, переполнение, неизвестные команды,
лишние и пропущенные операнды приводят к явной ошибке с номером строки.
Исходник проверяется целиком до вывода результата. Успех — код 0,
ошибка файла/программы — код 1, ошибка CLI — код 2.

## Модули

`src/commands.py` — коды команд, ширины полей и разбор строки.
`src/parser.py` — чтение CSV и список словарей полей.
`src/assembler.py` — аргументы, тестовый вывод и обработка ошибок.
`src/codec.py` — двоичная упаковка, распаковка и форматирование байтов.
`src/machine.py` — регистры, разреженная память и цикл fetch/decode/execute.
`src/interpreter.py` — CLI интерпретатора и JSON-дамп.
`examples/spec.csv` — все четыре примера из спецификации.

## Проверки

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest tests/ -q
make test PYTHON=.venv/bin/python
```

Проверяются все примеры PDF, границы полей, ошибки CSV/чисел и CLI.
Бинарные результаты и служебные файлы Python в Git не добавляются.
Коммиты каждого этапа оформляются Conventional Scoped Commits.

## Двоичный формат

Младшие шесть бит — opcode A. Поля B, C, D последовательно упаковываются
после него по ширинам из таблицы. Команда всегда занимает шесть байт,
порядок байтов little-endian. Неиспользуемые старшие биты равны нулю.
Decoder отвергает неизвестный opcode, неполную команду и ненулевой padding.
Некорректный исходник не заменяет существующий результат. Совпадающие
пути исходника и бинарного результата запрещены. Число команд печатается
и без `--test`; сам бинарный файл не содержит текстовых заголовков.

## Интерпретатор: этап 3

```bash
python3 -m src.assembler examples/copy.csv build/copy.bin
python3 -m src.interpreter build/copy.bin build/copy.json \
  --start 200 --end 203
python3 -m scripts.demo_stage3
```

Первые два аргумента — бинарная программа и выходной JSON. `--start`
и `--end` обязательны, диапазон включительный. При запуске все регистры
и данные равны нулю. Программа хранится в отдельном массиве байтов,
данные — в разреженном словаре: все 26-битные адреса доступны без
выделения массива на 67 миллионов ячеек. Чтение незаписанной ячейки даёт 0.
Значения — целые числа Python без аппаратного переполнения. Индиректный
адрес записи берётся именно из R[C], а не из самого поля C.

Команды выполняются последовательно до конца файла; переходов и HALT
нет в спецификации. Пустой/обрезанный бинарник, неизвестный opcode,
padding и адрес за пределами 26 бит отклоняются с кодом 1. Дамп пишется
только после успешного исполнения. Совпадение путей бинарника и дампа
запрещено. JSON содержит `start`, `end` и объект `memory` со строковыми
адресами, включая нулевые значения.

`examples/copy.csv` самостоятельно инициализирует M[100..103] значениями
`[7, 11, 19, 23]`, затем копирует их в M[200..203]. Данные не подставляются
интерпретатором. Демонстрация запускает настоящий ассемблер и интерпретатор
и сохраняет фактический дамп в `reports/stage3.json`. Бинарники остаются
во временном каталоге и в Git не попадают. Демонстрации надо запускать
из соответствующих веток. Для этапа 3 отдельный pytest-прогон не запускался.
